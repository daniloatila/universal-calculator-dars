# Date & Time operations, sources and bounds

[Português brasileiro](limits.pt-BR.md)

The Rust evaluator accepts proleptic Gregorian dates from `0001-01-01` through `9999-12-31`. Civil operations count calendar dates. Absolute durations count elapsed nanoseconds on the supported time scale. A local day spanning a daylight-saving transition can therefore represent 23 or 25 hours of elapsed time. Inputs and result keys below are the language-independent forms used in Calculation Proof. [Gregorian leap-year rules](https://aa.usno.navy.mil/faq/leap_years) · [ISO 8601](https://www.iso.org/iso-8601-date-and-time-format.html) · [Rust evaluator](../../../crates/dars-universal/src/date_time.rs)

| Operation | Input and options | Result and convention |
| --- | --- | --- |
| `difference` | `start\|end`, two `YYYY-MM-DD` dates | `days=N; weeks=W; remaining_days=D`. Subtract the start from the end in civil days and divide by seven with truncation toward zero. An eight-day reverse difference gives −1 week and −1 remaining day. |
| `age` | `birth\|reference`, two dates | `years=Y; months=M; days=D; total_days=N`. Find the largest whole-month shift from birth that fits, clamping to the month end if necessary. Split that shift into years and months, then count remaining days. A February 29 anniversary falls on February 28 in a common year under this convention. A reference before birth is outside the domain. |
| `period` | One date. Optional signed integer strings `years`, `months`, `weeks`, `days`, each defaulting to `0`. `overflow` is `clamp` by default or `reject`. | `date=YYYY-MM-DD`. Apply the net shift `12 × years + months`, then the net offset `7 × weeks + days`. If the original day is missing in the target month, `clamp` selects the last day and `reject` returns `domain`. Intermediate and final dates must fit the supported calendar. |
| `calendar` | One date | `weekday`, `day_of_year`, `iso_year`, `iso_week`, `leap_year`, `days_in_month`. Monday is 1 and Sunday is 7. ISO week 1 contains January 4. The ISO year can differ from the Gregorian year near New Year. |
| `business_days` | `start\|end`, with optional `weekdays` and `holidays` lists | `business_days=N`. Count eligible dates after the earlier date through the later date, including that later date when eligible. Reverse input negates the count. Equal dates return zero. |
| `deadline` | One date and required signed integer string `count`. `basis` is `business` by default or `civil`. Business accepts `weekdays` and `holidays`. | `date=YYYY-MM-DD`. Positive and negative counts walk forward and backward, excluding the start date and including the target. Zero returns the start date. Civil mode advances by all calendar days and accepts no weekday or holiday list. |
| `timezone` | Local `YYYY-MM-DDTHH:MM[:SS[.fraction]]`, `from`, `to` and optional `disambiguation` | `local`, `utc`, `from_offset`, `to_offset`, `from_dst`, `to_dst` and `resolution`. Resolve the source local time to an instant and read that instant under the target rules. Outputs include seconds and preserve a nonzero fraction up to nanoseconds. |
| `duration` | `start\|end`, two `YYYY-MM-DDTHH:MM:SS[.fraction]` timestamps with `Z` or `±HH:MM` | `seconds=N.nnnnnnnnn`, signed and displayed with exactly nine fractional digits. Normalize each explicit offset to UTC and subtract the start instant from the end. |

## Business calendars and deadlines

`weekdays` is a comma-separated list of ISO weekday numbers from 1 through 7. Its default is `1,2,3,4,5`. A custom nonempty set can include Saturday or Sunday. `holidays` is an optional comma-separated list of up to 23 date entries. The evaluator trims and deduplicates list entries, then excludes supplied holidays that fall on selected weekdays. Use the applicable jurisdiction's dates when modeling a national or local calendar. The generic default contains weekdays only and the module supplies no observed holidays or substitution rules. Calculation Proof records `calendar_version=custom-weekdays-holidays-v1`, the weekday set and any supplied holiday dates. Other civil operations record `proleptic-gregorian-v1`. [Business calendar implementation](../../../crates/dars-universal/src/date_time/business.rs)

Business counts use complete weeks, a remainder of fewer than seven days and the applicable supplied exclusions. Deadlines find the closest date in the requested direction with the desired cumulative count by bounded binary search. In the backward direction the target is included and the start is excluded. This differs from reversing the argument order of `business_days`, which always excludes the earlier endpoint before applying the sign. [Civil calendar implementation](../../../crates/dars-universal/src/date_time/civil.rs) · [Business calendar implementation](../../../crates/dars-universal/src/date_time/business.rs)

## Named zones and elapsed time

Named zones use the same bundled IANA TZif bytes on Windows and WebAssembly. Enter `UTC` or a case-sensitive name in the bundle such as `America/Sao_Paulo`, `Europe/London` or `Asia/Kathmandu`. The engine performs exact name lookup, then passes the embedded bytes to Jiff. The host time zone, installed zone files and network access play no part in a conversion. Calculation Proof records the source and destination names, the requested and applied disambiguation and `tzdb_version=2026f`. Historical signed offsets are shown as `±HH:MM` or `±HH:MM:SS` when second precision is needed. Results apply to the rules known by this snapshot, including its projections. [IANA 2026f](https://www.iana.org/time-zones/releases/2026f) · [TZif format](https://www.rfc-editor.org/rfc/rfc9636.html) · [Pinned data crate](https://docs.rs/jiff-tzdb/1.0.0/jiff_tzdb/) · [Zone implementation](../../../crates/dars-universal/src/date_time/instant.rs)

`disambiguation=reject` is the default. A skipped local time returns `nonexistent_local_time` under all disambiguation settings. A repeated local time returns `ambiguous_local_time` unless `earlier` or `later` is selected. These settings choose by UTC instant order. An ordinary local time reports `resolution=unambiguous`. [Named zones and local-time ambiguity](https://www.rfc-editor.org/rfc/rfc9557.html) · [Jiff time-zone API](https://docs.rs/jiff/1.0.3/jiff/tz/struct.TimeZone.html)

The source and target DST booleans follow the IANA `rearguard` variant bundled by Jiff. Calculation Proof records `tzdb_format=rearguard`. For example, `Europe/Dublin` reports daylight-saving status true in summer and false in winter under this variant. An IANA build using negative winter DST can invert those booleans while giving the same UTC instant and offsets. [Jiff changelog](https://docs.rs/crate/jiff/1.0.3/source/CHANGELOG.md) · [Upstream explanation](https://github.com/BurntSushi/jiff/issues/258)

Named-zone conversions require the source, UTC and target dates to fit the supported civil years. The pinned Jiff `Timestamp` adds an upper UTC bound of `9999-12-30T22:00:00.999999999Z`. The elapsed-time operation with explicit offsets accepts UTC instants through the last nanosecond of `9999-12-31`. Its RFC 3339 subset takes uppercase `T` and `Z`, required seconds, optional one to nine fractional digits and a known offset. The parser excludes leap seconds, `24:00` and `-00:00`, which RFC 3339 reserves for an unknown local offset. Named-zone input also excludes leap seconds and `24:00`. All successful operations use exact integer or calendar arithmetic and record no numerical approximation. [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339.html) · [Jiff timestamp range](https://docs.rs/jiff/1.0.3/jiff/struct.Timestamp.html) · [Instant parser and arithmetic](../../../crates/dars-universal/src/date_time/instant.rs)

## Validation and dependency choice

The request engine bounds each expression to 4,096 UTF-8 bytes and each string option to 256 UTF-8 bytes. Named zone identifiers have a separate 64-byte parser cap. The absolute value of each period component and deadline count is capped at 4,000,000. Malformed dates, unrecognized zone names and invalid option formats return `invalid_input`. Domain failures include age before birth, an unavailable day under `overflow=reject` and arithmetic outside the supported date range. Resource limits have a separate `limit` error. [Request envelope](../../../crates/dars-universal/src/lib.rs) · [Date & Time parser](../../../crates/dars-universal/src/date_time.rs)

Jiff 1.0.3 provides Gregorian civil dates, TZif-backed named zones and explicit ambiguity detection. The lock selects `jiff-core` 1.0.2 and `jiff-tzdb` 1.0.0. `time::OffsetDateTime` supports explicit offset timestamps, and `chrono-tz` generates Chrono zone implementations from IANA data. Jiff with the bundled snapshot covers the named-zone requirements and supports the same lookup path on both targets. [Jiff API](https://docs.rs/jiff/1.0.3/jiff/) · [time offset API](https://docs.rs/time/latest/time/struct.OffsetDateTime.html) · [chrono-tz API](https://docs.rs/chrono-tz/latest/chrono_tz/) · [Dependency declarations](../../../crates/dars-universal/Cargo.toml)

The historical Chrono `localtime_r` advisory is RUSTSEC-2020-0159. Chrono 0.4.45 remains in the workspace lock through `serde_with` metadata. The selected desktop and Date & Time WebAssembly dependency trees omit Chrono. The local `cargo audit --deny yanked` check for this stage used 443 advisory entries and found zero vulnerabilities, with three existing warnings elsewhere in the workspace. Reproducible checks use the independent Python date, arithmetic and pinned IANA oracle.
