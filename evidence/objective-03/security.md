## Inputs, isolation and limits

Rust evaluates calculator inputs through operation-specific parsers with field, size, domain and algorithm bounds. Source text and metadata travel to the worker as data. The tested failure classes include unsupported operations, bad bindings, duplicate or incompatible fields, oversized inputs or outputs, invalid Unicode, singularities and operations outside their mathematical domain. The CLI/WASM oracles check structured errors and numerical semantics independently. The native and browser surfaces share the same Rust calculations. [Rust request contract](../../crates/dars-universal/src/lib.rs) · [Mathematical limits by module](REPORT.md#module-validation)

The calculation-record viewer checks schema, UTF-8 bytes, shape, keys, nesting and duplicate fields before rendering literal data. The 128 KiB file ceiling also applies to imported Standard records. The local import identifies the record as unverified and displays it without evaluation. The exported JSON contains calculation context, including explicitly entered monetary quote metadata when relevant. Downloads are initiated locally by the user. [Calculation record contract](calculation-proof/contract.md) · [Structural schema](calculation-proof/schema.v1.json) · [Browser import tests](../../apps/web/tests/calculation-proof.spec.ts)

Advanced WASM is feature-isolated. The frontend loads an eligible tool's assets on demand and runs computation in a dedicated, bounded worker. Cancellation and disposal retire the worker and suppress stale completions. The existing module manager and scheduler govern admission, cancellation and hidden-work budgets. Browser tests exercise these behaviors with actual workers, and native runs sample their lifecycle. ## Network and native capabilities

Calculations use local application code and data. Converter uses manual offline rates with provenance and a stated date status. Date & Time uses bundled IANA transitions and explicitly supplied business-calendar rules. Tests of quote text, record handling and named time-zone conversion observe the expected absence of external requests. Local application storage is limited to explicit preferences and versioned assets. The Operations interface provides controls for session clearing, preferences, diagnostic consent and cache-only mode. Service-worker installation and browser-owned update behavior have their own scope. [Operations and privacy](../../docs/en/operations.md) · [Converter tests](../../apps/web/tests/converter.spec.ts) · [Date & Time tests](../../apps/web/tests/date-time.spec.ts)

Tauri scopes its content security policy to local app resources and WebAssembly evaluation. Its native WebView command registers the existing opt-in sensor capability. Credential round trips exercise a synthetic entry through the OS provider tests. The app command surface exposes the capability reader, and credentials remain outside the web bridge. The verification harness uses a temporary WebView2 profile and local DevTools endpoint for the isolated test process.
