# Objective 01 regression record

[Review report](REPORT.md) · [Reproduction](reproduction.md)

The calculation correction is commit `69fb558050644220f4bec3354d180e66df9bc013`. The final tested source is `460c2f05049acaa75da0035444150f5f4eaed801`. The original behavior was reproduced in a production build of `ea26c7f9d4d870d1ee06a8b95f60854d0da059d3` with the original entry, worker and WASM checksums matched. [Baseline execution record](baseline-memory.json)

| Area | Original behavior or inspection | Corrected execution and regression check |
| --- | --- | --- |
| Irrational percentage in memory | With `100` stored, `sqrt(2)%`, M+, MR and Enter produced an invalid expression because MR appended the stored source to the consumed input. Clearing the field before MR produced `101.414213562373095048802` because the reused `%` became relative to 100. | The same interaction now yields `100.014142135623730950488`. MR recalls an immutable interval reference and the Rust engine adds the two numeric values. `200+10%` still gives `220`. The native WebView2 smoke check also exercises the corrected flow. [Browser memory tests](../../../apps/web/tests/standard-revision.spec.ts) · [Windows smoke check](../../../scripts/verify-desktop.mjs) |
| Precision and reusable results | The original reuse helper fell back to the source expression for irrational results and exact values that exceeded the literal digit limit. The failure above demonstrates the effect of changing its syntactic context. Ordinary chaining from `1/2` to `2.5` passed in the baseline browser control. | Rust preserves reduced rationals or certified intervals across recall, result continuation and further arithmetic. Tests cover negative operands, empty-memory subtraction, fractions, `2^1000`, roots, powers, explicit `%` on a referenced operand, and repeated interval additions and subtractions that expose precision loss from prematurely rounded decimal text. The browser exercises memory, history, undo and locale changes together. [Structured WASM oracle](../../../crates/dars-core/tests/structured-oracle.py) · [Browser memory tests](../../../apps/web/tests/standard-revision.spec.ts) |
| Stale state and cancellation | The previous source used a running flag and lacked explicit cancellation, an independent history revision and cancellation of a pending memory write by MC. These gaps were identified by code inspection. | The current browser suite injects delays and checks cancelling or editing mid-job, MC during memory work, ensuring late completions preserve the next value, and clearing history during an older calculation. The current result and the cleared history are handled independently. [Browser memory tests](../../../apps/web/tests/standard-revision.spec.ts) |
| Worker stall and recovery | The previous adapter bounded worker startup at 15 seconds. After readiness, a posted job had no deadline when a reply never arrived. This failure path was identified by code inspection. | The production browser test intercepts the first worker script to simulate a ready worker that never responds to work. The job times out and calculation succeeds on a replacement worker without reloading. Deterministic unit tests cover startup and transport failures, malformed replies, stale replies, deadlines, queue bounds, abort, retry exhaustion and cleanup. [Production worker test](../../../apps/web/tests/worker.spec.ts) · [Worker unit tests](../../../apps/web/tests/worker.test.mts) |
