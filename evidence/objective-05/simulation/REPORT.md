# Simulation

The `simulation` module accepts `monte_carlo` with a canonical JSON string in `input`. Common fields are `bins` (1–64, default 20), `confidence_level` (0.5–0.9999, default 0.95) and optional `threshold`. Seeded recipes require `seed` (unsigned 64-bit decimal string) and `samples` (2–100,000, subject to the work budget).

| Model | Input fields | Output interpretation |
| --- | --- | --- |
| `distribution` | `distribution`, `parameters`, `seed`, `samples` | Independent draws from any supported Probability distribution |
| `random_walk` | `sd`, `steps`, optional `start`, `drift` and `shock`, plus seed and sample count | Terminal sum of independent normal increments; drift sensitivity from shared paths |
| `finance` | `initial`, `drift`, `volatility`, `steps`, optional `contribution`, `shock`, `currency` and `risk_level`, plus seed and sample count | Terminal wealth under hypothetical lognormal gross returns, fixed end-of-step contributions, and positive signed loss as adverse |
| `historical_risk` | `losses`, optional `risk_level` | Empirical summary of recorded losses with no random generation |

Finance recurrence is `wealth_next = wealth × exp(drift + volatility × z) + contribution`. Its inputs are per-step log-return parameters. The model uses independent standard normal `z`. The principal and contribution amounts use only the supplied currency label (default BRL). Fees, taxes and external returns data are outside this model. The projection describes the supplied hypothetical process and offers no guarantee of future wealth.

Financial loss equals contributions plus initial funding minus terminal wealth. The engine evaluates this through compensated per-step losses `−wealth × expm1(log_return)` to retain small losses or profits even when the displayed terminal wealth rounds to the funded amount. Positive values are adverse losses. VaR uses the left inverse of the empirical loss CDF at `ceil(n × level)`. Expected Shortfall averages the largest `n × (1−level)` losses with fractional weight for the boundary observation. `risk_level` defaults to 0.95 and accepts 0.5–0.9999. Mantissa and effective decimal scale are capped at 32 digits. The original decimal and rank calculations are retained before binary64 aggregation. For 100 losses `1..100`, level `0.56` gives VaR 56. Level `0.560000000000000000000001` gives VaR 57. Both reported approximate levels round to 0.56, and `loss_risk.level_exact` distinguishes them.

## Reproducibility and resource bounds

- The generator is reference PCG32 XSH-RR 64/32, revision `pcg32-xsh-rr/1`, fixed stream 54. Two 32-bit words yield a midpoint on the open unit interval. Sampling uses Box–Muller, log-gamma rejection with bounded attempts, inverse transforms or without-replacement operations according to the chosen law. All draws use an ordered serial stream without OS entropy. It is designed for simulation. [PCG reference](https://www.pcg-random.org/download.html) · [Box and Muller](https://doi.org/10.1214/aoms/1177706645) · [Marsaglia and Tsang](https://doi.org/10.1145/358407.358414)
- The engine retains the full requested sample count and enforces at most two million weighted work units, 1,000 steps per path, 512 observed historical losses, and at most 4,096 input bytes. Cheap independent draws cost one unit. Path-based and without-replacement models charge per step or draw. Binomial, negative binomial, and Poisson charge for numerical inversion. Each step call also limits its work to 32,768 units regardless of requested batch size. Magnitudes of the simulated outcome, loss and sensitivity difference are bounded by `1e140`.
- Isolated WASM exposes `SimulationTask`. `step(1..4096)` reports actual `completed`, unchanged `total` and `done`. `finish()` returns the normal calculation proof after all samples complete. Releasing the task discards pending samples. The browser worker yields between batches and can be terminated. The CLI executes the same kernel serially to completion. Fixed seed and recipe remain bit-for-bit stable across batch boundaries in the same build and target. The Node parity suite checks both exact and numerical CLI/WASM equivalence and release of a partial task. Physical browser cancellation and recovery are covered by the integrated audit.
- Mean and sample variance use shifted two-pass compensated accumulation. Empirical quantiles use Hyndman–Fan type 7 with exact integer rank coordinates and binary64 interpolation. Histograms are left-closed/right-open except for the final right-closed bin. Constant series use one bin. Event frequency is the fraction with `X ≥ threshold`. The Wilson interval describes uncertainty in that frequency for sampled data.
- Monte Carlo standard error for the mean is `sample SD / sqrt(n)` where the variance of the model is finite. An approximate normal CLT interval is emitted from 30 draws. Highly skewed or heavy-tailed distributions can have poor coverage. Historical observations have no Monte Carlo error. The proof records precision, method, seed, model, request parameters, fixed serial order, observed sample count and stopping status. Those fields support replay without claiming a certified error bound.
- Common random numbers are used for the paired drift sensitivity. Antithetic pairs and stratification can reduce variance for particular smooth, monotone estimates, but change the error calculation for event and quantile summaries. This implementation retains independent paths for the general estimator. Importance sampling would require a justified proposal and weight diagnostics for each model. The measured generic workload provides a baseline for evaluating that extension.

## Reproduce

Run `python -B tests/verify-simulation.py target/release/dars --out evidence/objective-05/simulation/tests.json --benchmark-out evidence/objective-05/simulation/benchmarks.json` with the locked test-only SciPy and NumPy environment. The independent generator checks reference PCG words and verifies normal, random-walk and financial paths. Distribution moments, empirical ranks, VaR boundaries, near-zero losses, histogram conservation, supported seeds, input limits and stable errors are checked separately. Then run `node tests/verify-simulation-targets.mjs target/release/dars` against generated WASM. See [test receipt](tests.json), [benchmarks](benchmarks.json) and [acceptance](acceptance.json).
