# Reprodução do Objetivo 05

[English](reproduction.md)

1. Use o branch de revisão para obter os scripts da auditoria. Compile a aplicação a partir do commit de código auditado registrado na aceitação. Compile a CLI com `cargo build --release --locked -p dars-cli`, prepare o wasm-bindgen fixado com `node scripts/install-wasm-bindgen.mjs` e execute `node scripts/build-wasm.mjs`. No host Windows do projeto, carregue `scripts/dev-env.ps1` para usar as ferramentas já instaladas. O build produz o WASM Standard e 21 módulos especializados.
2. Execute `npm ci --ignore-scripts --prefix apps/web`, `npm run build --prefix apps/web`, `npm test --prefix apps/web`, `cargo fmt --all --check`, `cargo clippy --locked --all-targets -- -D warnings` e `cargo test --locked`. O workflow relaciona as regressões matemáticas e financeiras.
3. Instale as dependências Python de teste com os hashes dos dois arquivos de requisitos em `tests/`, em ambiente isolado. Execute os scripts `tests/verify-<módulo>.py` com o caminho da CLI. Use `--scipy` em Otimização. Rode `node tests/verify-simulation-targets.mjs`, `node tests/check-science-kernel-targets.mjs` e `node tests/check-data-targets.mjs` indicando a mesma CLI para comparar WASM e nativo. Dois testes complementam os oráculos da CLI de lançamento. O comando `python -B tests/verify-data-import.py <CLI>` verifica 55 contratos de importação. O comando `python -B tests/verify-optimization-boundaries.py <CLI>` verifica 12 casos de fronteira de otimização e gráficos.
4. Em `apps/web`, execute `npm run test:e2e` para produzir o relatório Playwright. Na raiz, execute `node tests/verify-web-offline.mjs`. A suíte cobre cálculos, os cinco perfis, telas pequenas e RTL, exportação, uso offline, cancelamento, recuperação e trocas direcionais de idioma. Use um relatório completo para compor a matriz.
5. Execute `node benchmarks/science-data.mjs` para medir quatro tamanhos de tabela e conferir os totais exatos. A etapa de cobertura no workflow produz o relatório de linhas instrumentadas, com a definição do denominador.
6. No Windows, confira o pacote hospedado por meio de `scripts/verify-science-windows-artifact.ps1` com o ID do artefato, ID da execução e commit. Rode `node scripts/verify-desktop.mjs --objective-05 --exe <candidata>` para a regressão histórica e `node scripts/verify-science-desktop.mjs <exe-0.4.1> <exe-candidata> <recibo> <pasta-de-saída>` para a comparação no Windows interativo. O mecanismo valida hashes e fecha os processos que abriu.

Tempos e medições físicas dependem de máquina, WebView2 e atividade do sistema. A abertura inicial da Standard e o uso offline de módulos já preparados são cenários distintos. [Workflow](../../.github/workflows/ci.yml) · [Protocolo de memória](../objective-02/revision-02/memory-debt.pt-BR.md)
